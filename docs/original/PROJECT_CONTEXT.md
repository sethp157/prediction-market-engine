# Project context

## Confirmed intent

The user selected **test viability first**: investigate whether repeatable prediction-market edge exists. Learning and a useful portfolio project are secondary benefits, not substitutes for evidence of viability.

The user wants incremental research, mathematical documentation, explicit decisions before advancement, durable context, and guardrails for AI-assisted work. The evaluation engine should emerge from the questions and evidence the program actually needs.

## What a useful outcome looks like

- A supported reason to continue evaluating a narrowly defined method; or
- A supported reason to stop or revise because the apparent advantage disappears, cannot be evaluated honestly, or is impractical to exploit; or
- An explicit inconclusive result identifying the missing evidence and whether obtaining it is worthwhile.

No monthly-income target is an acceptance criterion. The project must not optimize its analysis toward a desired profit figure. “Economically meaningful” remains undefined until the required costs, effect sizes, capital assumptions, and resource constraints are specified.

## Initial scope

Documentation and Q1 research only. No selected venue, market class, strategy, software architecture, model API, or capital allocation. The charter's references to “Astra” describe the intended AI research/forecasting role; record the actual model identifier and capabilities when a run is designed. Do not assume access to a particular model or API.

## Open constraints

| Constraint | Current status | Resolve before |
| --- | --- | --- |
| Weekly research time and initial review date | Undecided | Committing to a sustained research plan |
| Total research and API spend | Undecided; no new paid work authorized | Any paid data or compute commitment |
| Data availability, access rights, and retention | Unverified | Using a dataset in an experiment |
| Market universe and forecast horizon | Undecided | Finalizing the evaluation protocol |
| Minimum worthwhile effect and evidence standard | Undecided | Freezing a confirmatory experiment |
| Capital, loss limits, and execution permissions | Outside initial scope | Any future live-pilot proposal |

Ask about these when the active question requires them. Do not block useful Q1 work by collecting every future preference at once.

## Communication

Use defined notation plus concise interpretations. Separate established facts, assumptions, candidate decisions, and unanswered questions. Make tradeoffs reviewable; do not overwhelm the user with an entire downstream architecture at the first gate.
